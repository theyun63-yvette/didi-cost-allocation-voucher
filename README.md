# 滴滴车费自动分摊与凭证生成工具

本项目是可在 macOS 本地运行的 Streamlit MVP。金额、比例、科目、部门、项目、税额、尾差和借贷校验全部由确定性 Python 代码执行；财务金额使用 `Decimal`，舍入模式为 `ROUND_HALF_UP`。

平台采用纯本地计算模式：上传的Excel仅由本机Python进程读取和计算，不调用外部AI API，不上传业务文件。项目内`.streamlit/config.toml`已关闭Streamlit匿名使用统计，并将工具栏设为查看模式，以隐藏Deploy及开发者推广入口。

## 启动方法

### 双击启动

在 Finder 中双击项目根目录下的 `start.command`。

首次启动会在项目目录创建 `.venv` 并安装 `requirements.txt`。浏览器通常会自动打开；如未打开，请访问终端显示的本地地址（默认 `http://localhost:8501`）。

### 终端启动

```bash
cd "/你的路径/平台开发"
./start.command
```

也可手动执行：

```bash
.venv/bin/python -m streamlit run app.py
```

## 使用流程

1. 选择目标月份，上传人员信息表、研发工时成本分摊表和原始滴滴账单。
2. 系统先生成订单分摊明细、岗位项目汇总、清洗日志和异常清单。
3. 下载 `处理明细.xlsx`、`分摊汇总.xlsx` 和 `异常清单.xlsx`进行人工核对。
4. 点击“我已人工确认分摊明细和汇总无误，进入凭证计算”。
5. 上传凭证标准模板，系统才执行税额、尾差、会计重分类、借贷校验和凭证生成。
6. 不存在阻断性异常时下载 `月度凭证.xlsx`。

输入文件或目标月份变化后，之前的人工确认自动失效，必须重新核对并确认。

系统不依赖固定文件名，而是按工作表名称、技术表头和受控字段别名识别文件。

## 样例运行

```bash
.venv/bin/python scripts/run_sample.py
```

输出目录：

```text
output/sample-2026-07-v1.3/
```

当前样例按补充规则生成以下计算和检查文件：

- `处理明细.xlsx`
- `分摊汇总.xlsx`
- `异常清单.xlsx`
- `月度凭证.xlsx`（人工确认第一阶段结果且不存在阻断性异常时生成）

7月样例识别930笔有效订单、企业实付58,616.46元。每笔订单先按 `ROUND_HALF_UP(企业实付金额/1.03, 2)` 计算不含税金额，逐笔合计为56,909.24元，税额为1,707.22元。程序从原始字段重新匹配人员和工时，不读取账单中已有的XLOOKUP、金额公式或数据透视表结果。项目汇总与补充说明中的参考金额完全一致。

样例工时表中部分员工的“非研发占比”为空。按照最新补充规则，空白表示未从事非研发项目，系统按0处理并记录提示日志；如果研发项目比例合计为1则通过，如果全部比例合计不为1仍然阻断。7月样例通过全部计算和凭证校验。

## 输入规则摘要

### 人员信息表

至少包含唯一可识别的：

- 姓名
- 部门名称或岗位（二者至少提供一个）

可选：员工编号、手机号、部门编码、类型。`类型`目前不参与金额或会计归属计算。相同姓名对应同一会计归属时去重并记录提示；对应多个会计归属时阻断。只有部门名称时，以部门名称作为默认会计归属；提供岗位或会计归属列时，优先使用该列。历史人员差异还可在 `employee_role_overrides` 中按姓名受控配置。

### 工时分摊表

目标工作表必须命名为：

```text
工时分摊-YYYY.M
```

必须包含：姓名、岗位、当月已经生效的研发项目列及非研发占比。Coding、Prediction、AI4SCI、Multimodel、Cowork、Trading适用于现有全部月份；Evaluation自2026年6月启用，因此2026年1—5月缺少Evaluation列时按0处理并记录提示，2026年6月及以后缺少该列则阻断。岗位不参与人员表姓名匹配，但必须与最终会计归属类别完全一致。研发项目比例空白按0处理并记录清洗日志；非研发占比空白表示未从事非研发项目，同样按0处理并记录日志，之后仍独立校验全部比例合计。没有“姓名＋会计归属类别”完全一致的工时记录时，自动按非研发100%处理。

### 滴滴账单

必须包含：所属账期、企业订单号、下单人姓名、企业实付金额、企业实退金额。账单汇总区域必须能按字段名唯一识别结算周期；`本期`按该结算周期解释。退款时间用于判断是否跨月，“企业应付金额”如存在则用于核对退款净额。同月部分退款按“企业实付金额－企业实退金额”作为有效价税合计继续计算；同月全额退款净额为0，自动排除并记录；跨月退款、退款月份不明、退款金额异常、负数、红字和重复订单号仍然阻断。

### 自动计算与汇总

- 仅读取原始账单字段，不使用账单中的辅助公式或数据透视表缓存结果。
- 无退款订单的有效价税合计等于企业实付金额；同月部分退款订单的有效价税合计等于企业实付金额减企业实退金额。
- 每笔订单以有效价税合计除以1.03并按2位小数舍入，再乘各项目比例和直接读取的非研发占比。
- `处理明细.xlsx`包含一单一行的订单分摊明细、会计重分类追溯、匹配结果、清洗日志和运行日志。
- `分摊汇总.xlsx`按会计归属类别/岗位汇总七个研发项目金额、非研发金额和合计金额。
- 单笔分摊合计及汇总合计均必须与有效订单不含税金额一致，否则阻止生成凭证。

### 凭证模板

必须存在且唯一识别以下技术表头：

- `book.number`
- `bizdate`
- `bookeddate`
- `vouchertype.number`
- `billno`
- `edescription`
- `account.number`
- `debitlocal`
- `creditlocal`
- `currency.number`

模板中的工作表名称、表头、字段顺序、隐藏工作表和辅助工作表会保留。旧数据区会在内存副本中清空并写入本月凭证，原始模板不会被修改。

## 业务配置

所有业务常量和映射均集中在：

```text
config/rules.yaml
```

包括税率、容差、尾差阈值、部门、项目、会计科目、岗位规则、受控人员会计类别覆盖、供应商、账簿、凭证字和币种。部门006为停用状态，程序禁止输出。

### 公开仓库与本机人员配置

公开的 `config/rules.yaml` 不包含真实员工姓名。若需要按姓名覆盖会计归属，请在本机创建不会提交到GitHub的 `config/rules.local.yaml`：

```yaml
employee_role_overrides:
  员工姓名: 算法
```

程序启动时会自动将该本机配置覆盖到公开基础配置之上。

## 当前限制

- 仅支持 `.xlsx`。
- 同月部分退款按净额处理，同月全额退款自动排除；不处理跨月退款、退款月份不明、负数订单、红字、混合税率、多供应商、多主体或同月多张凭证。
- 不进行姓名拼音或模糊匹配。
- 不提供数据库、登录、审批和历史批次管理。
- 输入模板差异超出受控别名时会阻断，需要修改配置或源文件。
- Excel金额单元格最终以数值写入；财务计算过程始终使用 `Decimal`。


## GitHub 数据安全

本仓库只保存程序代码和规则配置。`.gitignore`默认排除Excel、CSV、日志、进程文件、虚拟环境及`output/`中的所有实际运行结果。人员信息表、工时表、滴滴账单、凭证模板和生成文件应仅保存在本机，不应提交到GitHub。
